# Mayday: 1080p source switching on 14 September 2026

The active Mayday movie repeatedly changed between YTS 1080p and 720p sources because the TV could not decode the HLS video generated by the helper. Download throughput was healthy: the inspected 1080p WEBRip torrent reported 1,529,374.6 bytes/second and 99 connected peers. The app displays this as MB/s, not Mbps. The source file's average bitrate was 2,638,851 bits/second (about 0.33 MB/s).

## Evidence

- The TV remained at time 0 and eventually reported `MEDIA_ELEMENT_ERROR: Format error`.
- Its retained log recorded the final HLS stop at 19:33:03.948 UTC. The stack led through `watchPlaybackHealth` to `recover`: the 30-second startup deadline had expired without advancing playback. This deadline does not depend on torrent speed.
- An isolated session using the same active torrent prepared a playlist with over 30 seconds of segments. The source MP4 decoded successfully, but the generated first segment failed decoding. FFprobe reported H.264 with width/height 0; FFmpeg reported missing start codes and invalid picture headers.
- The first source packet begins with a one-byte SEI NAL: its MP4 length prefix is `00 00 00 01`. FFmpeg's automatic bitstream-filter detection mistakes that prefix for an Annex B start code. The remaining MP4 length-prefixed video packets are then copied into MPEG-TS with invalid framing.
- Repeating the remux with `-bsf:v h264_mp4toannexb` produced a decodable 1918×802 H.264 segment with stereo AAC. This is the source's cropped 1080p picture size.

## Change and validation

`hls-session.mjs` explicitly applies `h264_mp4toannexb` to HLS video output. Existing buffer sizes and fallback timers are unchanged by this fix.

The regression test creates a synthetic MP4, replaces its initial encoder SEI with a one-byte SEI plus equal-size filler, and verifies source and output frame decoding. It failed against the original implementation and passes with the fix. No movie content is included in the test fixture.

All 12 targeted tests passed:

```sh
node --test hls-session.test.js playback-health.test.js remote-helper.test.js
```

The running `moviesdb-helper.service` was restarted, and only the already failed Mayday 1080p WEBRip selection was retried. Live TV samples are recorded in the adjacent JSON file. The native player's `webkitDecodedFrameCount` stays zero even while playback advances, so that counter is not used as evidence of successful playback.

Nine samples over 80 seconds showed uninterrupted clock advancement from 15.953 to 95.995 seconds, the same 1080p source throughout, readyState 4, no media error, and roughly 28–29 seconds buffered ahead. This is a short live validation, not a full-movie endurance test.
