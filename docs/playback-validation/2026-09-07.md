# LG TV playback validation — 7 September 2026

Follow-up: [111Movies is now fixed and passed the four-title TV run](2026-09-07-111movies-fix.md). The results below record the earlier baseline.

Overall result: **not a full end-to-end pass**. The native player works with some sources, but buffering and provider failures remain.

Tests ran on the configured LG webOS TV, through the installed Movies app and its HTTPS helper. These are actual media-clock measurements, not mocked playback or merely opened player windows. Controls were invoked through the TV debugger, with synthetic LG Back events. Physical remote-button operation, audible sound, and full-length viewing were not established by this run.

| Title | 111Movies | Native result |
| --- | --- | --- |
| The Shawshank Redemption | Provider loading error; no video element | Initial playback succeeded but an unexplained source switch invalidated resume/seek. Rerun sustained approximately one minute and passed pause/resume, forward/backward seeking with subsequent progress, and Back. |
| The Matrix | Same provider error | Played but buffered during the sample. Pause/resume, forward/backward seeking, and Back passed. |
| Rick and Morty S1E1 → S1E2 | Same provider error | Initial 1080p episode stalled around 15 seconds and recovered. Controls and episode transition passed. A selected 720p source subsequently sustained approximately one minute and passed transport checks. |
| Breaking Bad S1E1 → S1E2 | Same provider error | Episode 1 started after fallback, then stalled. Resume and forward seek missed their deadlines. Episode 2 exhausted automatic sources without playing. Back passed. |

All four baseline cases restored the selected title after Back. 111Movies redirected to `player.vidlove.cc`, which displayed “Something went wrong loading the player.” No movie/show video was present in those provider frames. 111Movies remains the first/default source as requested.

The baseline measured six five-second intervals after startup. “Continuous” requires readyState ≥ 3 and at least three seconds of progress per interval; merely advancing slightly while buffering is not a pass. Follow-ups sampled approximately a minute and checked advancing playback for six seconds after each seek. Baseline seek checks established readiness at the new displayed position, not long-term stability there.

## Changes supported by this run

- Native episode playback on TV now prefers available 720p sources, matching movie playback; higher qualities remain selectable. This is supported by the Rick and Morty source comparison, not a claim that every 720p source works.
- Overlapping subtitle lookups/retries could duplicate menu entries. A request counter now rejects stale subtitle results, with a browser regression covering the race.
- Added `tv-device-check.mjs` for repeatable opt-in device checks and JSON reports. It returns failure when primary-provider or required playback checks fail.

Captions were off in the baseline/follow-up playback samples; those samples do not validate subtitles. Final explicit-caption validation is recorded below.

Raw measurements: [baseline](2026-09-07-baseline.json), [targeted reruns](2026-09-07-followup.json).

Final explicit-caption check passed on Rick and Morty S1E1: the selected default was `720p · 82 seeds · Torrentio`; the menu contained one Off entry and one English entry, and enabling English produced visible caption text. The previous Off preference was restored afterward. The final app was left on the unfiltered browsing screen.

Final automated regressions: 7/7 TV browser tests passed; 417 unit tests passed, 13 opt-in tests skipped. These fixture results do not override the live failures above.
