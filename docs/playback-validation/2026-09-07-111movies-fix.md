# 111Movies TV fix — 7 September 2026

**Correction:** This run established media-clock progress, but did not check the video’s rendered size. The user correctly reported that playback was still broken: the video was 0 × 0 pixels. See [the follow-up investigation](2026-09-07-111movies-visible.md). The historical results below are not a visual playback pass.

## Cause and implementation

The provider redirects to `player.vidlove.cc`. Its player called `navigator.mediaSession.setPositionState` without checking support, producing a TypeError in this TV’s Chrome 79 browser. The exception was caught by the provider’s error boundary and displayed as “Something went wrong loading the player.” Chrome introduced this optional media-session method in [Chrome 81](https://developer.chrome.com/blog/new-in-chrome-81).

The helper installs a narrowly scoped compatibility guard before the provider runs, through the existing LG Developer Mode connection. The original provider still delivers the video. The helper reconnects after the app restarts; its inspector forwarding binds only to loopback. Keep the helper computer running and the TV’s Developer Mode connection available.

App-owned controls provide play/pause, backward/forward seeking, and sound. Back from inside the provider exits fullscreen first, then closes playback and restores catalogue focus.

Controls were exercised through the TV debugger using DOM actions and synthetic key events. These results supersede the earlier 111Movies failures, not the separate native-source results.
